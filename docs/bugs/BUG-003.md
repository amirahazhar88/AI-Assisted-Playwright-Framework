# BUG-003: "Follow" on the article page calls `/profiles/undefined/follow` and does nothing

| | |
|---|---|
| **Status** | Open |
| **Severity** | High (follow from the article page is completely broken) |
| **Priority** | P2 |
| **Found by** | Automated test `tests/follow.spec.ts` (follow from the article page) |
| **Found on** | 2026-11-10 |
| **Component** | Frontend `ArticleActions.vue` |
| **Environment** | Local Docker stack, API `:3100`, frontend `:8080` |

## Steps to reproduce
1. Sign in as user A. User B has published an article.
2. Open B's article (`/article/<slug>`).
3. Click **Follow B**.

## Expected
`POST /api/profiles/B/follow`; the button changes to **Unfollow B**.

## Actual
- Request: `POST /api/profiles/undefined/follow` -> **404**.
- The button stays **Follow B**. No error is shown.

## Evidence
Network capture: `POST /profiles/undefined/follow 404`. Following from the author's **profile page** works (`tests/follow.spec.ts`, first test).

## Suspected cause
`ArticleActions.vue` builds the request from `profile.value.username` (profile store), which is not loaded on the article page, instead of `article.author.username`. The same function also checks `props.article.following`, but the article object has `author.following`, so the unfollow branch can never run.

## Automation
`tests/follow.spec.ts` › "follow and unfollow an author from the article page" is marked `test.fail()` linked to this bug.
