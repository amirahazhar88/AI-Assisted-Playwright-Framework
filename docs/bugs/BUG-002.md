# BUG-002: Settings cannot be saved when bio or image is empty; the error says "Unable to connect"

| | |
|---|---|
| **Status** | Open |
| **Severity** | High (a main feature fails for the most common case: a new user with no bio or image) |
| **Priority** | P2 |
| **Found by** | Automated test `tests/settings.spec.ts` (settings update) |
| **Found on** | 2026-11-10 |
| **Component** | Frontend `Settings.vue` + API `PUT /api/user` |
| **Environment** | Local Docker stack, API `:3100`, frontend `:8080` |

## Summary
The settings form always sends `bio` and `image` as strings. For a user who has not set them, they are `""`, and the API rejects empty strings with **422**. The user stays on the settings page and sees the unrelated message **"network Unable to connect to the server"**.

## Steps to reproduce
1. Register a new user (bio and image are empty).
2. Open `/settings`, change nothing or change only the bio, and click **Update Settings**.

## Expected
Settings are saved, and the app opens the profile page. (An empty bio or image is a normal state; the RealWorld spec allows `null`/empty.)

## Actual
- Request: `PUT /api/user` with body `{"user":{"email":"…","username":"…","bio":"hello","image":""}}`.
- Response: **422** "Invalid or missing data in the request body".
- UI: stays on `/settings` and shows "network Unable to connect to the server" (misleading; the server was reachable).

## Evidence (API only)

| Body | Status |
|---|---|
| `{"user":{"bio":"x"}}` (image omitted) | 200 |
| `{"user":{"bio":"x","image":null}}` | 200 |
| `{"user":{"bio":"x","image":"https://example.com/a.png"}}` | 200 |
| `{"user":{"bio":"x","image":""}}` | **422** |
| `{"user":{"bio":""}}` | **422** |

## Suspected cause
Both sides contribute: the frontend sends `""` instead of omitting or nulling empty fields, and the API's validation does not accept empty strings. The error mapper in the frontend also reports every non-field error as a connection problem.

## Workaround in tests
Happy-path settings tests fill both bio and a valid image URL. A separate test saves with an empty image and is marked `test.fail()` linked to this bug.
